# Performance and engineering audit — 0.7.5 working tree

This is a map of the reviewed performance-sensitive paths, their evidence, and the safest next decisions. It is not proof that every defect or optimization in the mod has been found: static review and simulated engine calls cannot establish all in-game paths, compatibility combinations, or visual results. The existing player configuration was not changed for this audit.

## Changes already made

- `death_face.lua`: reuse the global skeletal-component search for the missing-face diagnostic. If that search failed, retain the retry. This avoids a duplicate scan in the missing-face case, not the compatibility search itself.
- `object_lifetime.lua`: lifetime batches reuse validation performed in the same frame; both alive and held entry points retain frame-scoped safety. The practical gain in game is not yet measured.
- `gore_scheduler.lua`: log slow external-copy refreshes with cut count and pending stage. This is instrumentation, with no scheduling change.

Focused Lua simulations for these changes passed, as recorded in the technical notes. Real UE object lifetimes, custom-head compatibility, animation and frame times still need in-game observation.

## Priorities for the next game session

Compare the 0.7.5 slow-tick, character-position, lifetime and cut-stage lines; the copy-refresh line appears only at the configured slow threshold. One session can cover these together. The available older 0.7.4 log showed character-position work around 27–32 ms for 29–30 candidates and 52–126 ms for 51; guard batches 37–55 ms for 30 guards; and individual cut/opening stages around 22–27 ms. Those numbers are historical, not a measurement of the current build.
2. If lifetime or character-position work still dominates, measure calls and candidate counts before changing the refresh or distance policy (`main.lua` around `live_chars` and `char_at`; `object_lifetime.lua`). Longer caches could miss a new enemy, teleport or killing blow, and a stale UE object can crash the game. A smaller candidate set or combining already-required calls is worth evaluating only with those cases covered.
3. If the new copy-refresh timing overlaps a slow cut, investigate incremental synchronization (`gore_copies.lua`, `gore_scheduler.lua`). Preserve the current cut's copy synchronization and re-entry/recovery behavior: simply postponing it can reveal stretched geometry. If it is not slow, leave scheduling alone.
4. Investigate the existing native real-mesh enemy-waist failures documented in `TODO.md`: CH_M_NA_05, CH_M_NA_05_Var01 and CH_M_NA_31 gain 2, 2 and 5 visible stretched triangles respectively in the harness's flung-upper-body case. ## Other opportunities and reasons for restraint

- **Native seam centroids** (`native/sbslice/sbslice.c:2423`): each qualifying non-core section/side scans the vertices to compute its seam centre. Lazy collection in one pass could reduce repeated scans when many sections qualify. This has not been benchmarked and was not changed. The centre determines a sink chosen to prevent stretched loose clothing; any proposal needs representative section counts, timings, bit-for-bit output comparison against the existing cutter on passing and known-failing real meshes, and game appearance checks. Preserve the original per-section floating-point accumulation order and section bounds. A complicated cache is not justified by a theoretical loop count alone.
- **Global searches**: `main.lua` caches characters and tracks new objects; `enemies.lua:945` documents 50–90 ms searches and a move to one initial scan plus new-object watching; `glass.lua:65` documents HUD-search costs and backoff. Startup, reload and missing-object paths still need fallbacks. Search replacement should be driven by current timings and prove that late-created, re-created and mod-added objects are found. `death_face.lua` deliberately keeps its global fallback for off-tree custom heads.
- **Preloading and pools**: `gore_watch.lua` already paces requests, checks load conditions and retains late async requests for synchronous fallback; its comments record expensive async requests and startup constraints. `gore_pools.lua:21` times decal work, and its update and spawn budgets protect visual ordering. Revisit only if current traces identify these costs; removing the fallback or raising the budget can trade missing assets for hitches or crashes.
- **Native stats and object discovery**: `stats.c` documents an earlier 1.5–2 s synchronous boss search; the current incremental scanner limits work and rechecks parent links. `newobj.lua` and the native watcher protect the game-thread boundary and special photo-mode timing. Their extra checks and fallback modes are correctness mechanisms, not dead code.
- **Cut scheduling and geometry**: staged operations, section sink selection, bone borrowing, rollback, split fallback and copy refresh address observed animation, seam and recovery failures. Reducing stage count or removing a branch needs evidence from the specific stage and real meshes, including interruptions, outfit and custom-mod cases. Existing geometry tests do not prove rendered appearance or real physics.
- **Diagnostics and optional features**: `performance.lua` throttles ordinary hitch reports and pauses its GC probe during the busiest death frames. Photo mode, UI, settings, blood, stains, ragdoll and enemy features have different activation conditions; keep their lifecycle and restore paths intact. Settings overlay runs on load/reload, so simplifying it is unlikely to improve frame time. The native spawner has its own UI thread and delegates spawning to Lua on the game thread; its window alone is not evidence of a gameplay bottleneck.
- **Build/assets**: `build.sh` caches extracted assets and accounts for other installed mods' mount order, skipping containers it cannot read. This is build-time work, not per-frame cost. Faster invalidation or incremental extraction is a separate build-time project and must account for changed game files, mod order and incompatible containers. Do not discard overlays merely to speed the build.
- **Architecture and tests**: module count and large coordinator files alone do not prove overengineering. `ARCHITECTURE.md` explains why state transitions and cleanup stay coupled. Existing simulations include useful failure and retry cases but emulate UE behavior; `TESTING.md` documents log-only and fake-engine limitations. Retain cases until their unique behavior has another independent check. The focused real-mesh tests are not a substitute for the larger outfit sweep or game testing when geometry changes.

The reviewed areas include object lifetime and discovery, death and hit scheduling, cut copies and geometry, enemy behavior, loading, pools/effects, UI/photo/settings, native stats/spawner and asset/build tooling. This is a prioritized engineering review, not an exhaustive line-by-line proof of every script, asset, configuration or third-party combination. Further optimization decisions should follow measured hot paths and preserve the explicit fallback behavior above.

## Subsequent file-level pass (complete)

Coverage is tracked in `AUDIT_COVERAGE.md`; all executable sources and build tooling have been reviewed once for safe optimizations. The follow-up pass fixed a missing post-process photo hook, the cut-stretch diagnostic, requests exceeding the 64-object lifetime limit, a rounded-normal cap calculation, and repeated front shifts in the enemy knockdown queue. See the changelog and technical notes for focused checks and the synthetic queue benchmark. None establishes game behavior on its own.

The body-blood world-change restore now keeps failed writes for bounded retries; its interaction with stains is covered by focused simulations. `newobj.lua` now reports a class as watched only after a complete confirmed native registration; focused tests cover failed and truncated reconfiguration. Game behavior remains unverified.

The subsequent pass also fixed fewer-GC restoration after unavailable reads or failed writes, and added the missing outfit selector and retoc patches to the build cache key. These changes are covered by `perf_probe` and a complete `check-build` respectively; their in-game effects remain unverified.

`stats.c` still uses a linear visited-address list during the player-stat discovery scan (`stats_find`), unlike the bounded incremental boss scanner. It can become quadratic on pointer-rich actors and runs synchronously; measure actual player-discovery timing before changing it. A hash set must preserve scan order, limits, and both HUD-anchored and hit-candidate discovery.

Detached-head photo diagnostics (`photo_freeze.lua`) sample every named hair bone every fifth animation update even when no log line is emitted. This is limited to the detached-head photo path and exists to diagnose a reported hair snap. Measure cost in that mode and preserve an opt-in diagnostic before throttling or removing it.

**Open recovery risk:** `cloth_reset.lua` clears its collision snapshot before the native lifetime query succeeds; `photo_collision.lua` does the same on restore, and also drops a snapshot if its initial query fails. A transient bridge failure can therefore lose the values needed to restore collision (and the cloth simulation restart similarly drops its guard on failure). The large-batch fix prevents one known cause, but does not cover a bridge failure. This needs a lifecycle-aware retry design: world changes, a new photo/reset, and ragdoll takeover can invalidate old snapshots or make a delayed write unsafe. No change was made without those cases and focused failure-path coverage.

The file-level pass found cache identity problems in cut preparation: separate rules for unfaced enemies, physics-asset replacements, and world cleanup are now covered by focused simulations. It also fixed the native regrowth section-list terminator, with a synthetic failure-path case and real-mesh arm/regrowth checks. In-game results and the cost of the extra guarded physics lookups remain unmeasured.

A 0.7.2 report says Eve?s combat voice is silent in English and Latin American Spanish but not Castilian Spanish. The shipped 0.7.2 core pak replaces CSS_PC_EVE to add a DIE3 death-face entry. A read-back with the game containers present resolves all 53 pre-existing SoundSource paths to the same paths as the game asset; the current build does too. The installed game has en, es-MX and es localized attack cues and corresponding wave packages. This does not establish actual playback or exclude a localization/packaging interaction, and no game reproduction or report log is available here. No speculative change to the death-face fallback was made. Re-examined with the report screenshot: container listing shows CSS_PC_EVE exists only as the neutral package while voice cues and dialogue waves ship per-culture with symmetric counts (en/es/es-MX), and a direct JSON comparison of vanilla vs patched CSS shows identical import tables (184 entries, no path/class changes, DIE3 reusing an existing breath-cue import). The override predates 0.7.x by many versions and Lua never touches combat voice. No mechanism was found by which this override mutes two cultures only; no change shipped.

Native index-buffer reuse (`ib_indices`) checks pointer, length and 16 samples, not every index. This avoids a full engine index walk on later cuts, but cannot detect an in-place change outside those samples. No such change has been established for the shipped meshes; investigate if another mod mutates an existing index buffer, rather than dropping the cache without measuring the cost.

Native rim classification (`core_classify`) scans all rim points 40 times per populated section to find a median, and may repeat classification while fitting the centre; its touching-layer check can also compare pairs of points. This is a plausible cut-stage hotspot on section-heavy meshes, not a measured in-game bottleneck. If timing warrants it, cache per-point squared distances or group by section while preserving the existing bisection, ordering, ties and fallback behavior; compare exact classifications and cap outlines across the real-mesh cases before shipping.

## Closing verdict (all sources reviewed)

The coordinators (`main.lua`, `gore.lua`, `active.lua`), gameplay logic (`enemies.lua`, `bosses.lua`, `struggle.lua`, `blade_decision.lua`, `tables.lua`, `glass.lua`, `gore_smash.lua`), and build tooling were reviewed for safe wins. No further behavior-preserving optimization with a proven in-game benefit was found: per-tick loops are already gated and single-read, staged cuts/pools/deferred work are intentional hitch spreading, and the remaining native hotspots (seam centroids, island tally, sink scans, `core_classify`, band/ride selection) need bit-for-bit harness comparison plus game appearance checks before any change. The listed fallbacks (lifetime guards, copy sync, staged-cut rollback, preload retries, search fallbacks, exact restores) stay as they are. Further work should follow measured hot paths from one representative session, not more static passes.
